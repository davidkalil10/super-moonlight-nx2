# src/renderer

The console side: `moonlight/` is the HB package, built by its `build.js` from the HBV codecs
(`hbv.js`, `hbv2.js`) and `glslang-shim.sh` here. The package folder must be named after its id
(hbl-platform readPackage). Test: `node --test src/renderer/test/package.test.cjs` from the repo
root; it pins the committed shader and image hashes.

## Codecs

README.md "HBV1 and HBV2 slots" has the wire formats; this is what the code assumes.

- `hbv.js` is the only source of HBV1. Every macroblock is exactly nine words, so the fragment
  shader finds a pixel's data by index arithmetic and evaluates the IDCT at its own position.
  Fields are LSB first and may straddle a word boundary.
- `hbv2.js` is the reference decoder and a plan-driven reference encoder; the console decoder
  is `moonlight/backends/hblauncher.gpu-app/hbv2.glsl`. The integer IDCT is shared bit for bit
  with the shader and the C encoder, so P frames never drift. `ue()` reads its zero prefix from
  the low bits. Each chunk-list entry carries its bit offset, so chunks decode in parallel.
- Generated files start with `// Generated by tools/moonlight/hbv.js;` (and `hbv2.js;`,
  `ring.js.`). The paths are stale but stay: changing them changes the pinned bytes.
